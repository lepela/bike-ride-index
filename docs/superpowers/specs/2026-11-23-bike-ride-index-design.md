# 출퇴근 바이크 주행 지수 — 설계

작성 2026-11-23. 표시 규칙: **[결정]** 은 사용자가 정한 것, **[제안]** 은 설계자가 정한 것으로 사용자가 바꿀 수 있다.

## 1. 목적

겨울철 출퇴근에 바이크를 탈지 정하는 판단을 지수 하나로 보여 준다.

- 비가 온다고 무조건 타지 않는 것은 아니다. 강수량에 따라 판단을 달리한다. **[결정]**
- 눈은 가급적 피한다. **[결정]**
- 눈이 온 뒤 1~2일은 기온에 따라 도로 결빙을 따진다. 노면 온도는 추정치로 쓴다. **[결정]**
- 예보는 한 곳만 쓰지 않고 다섯 출처를 비교한다. **[결정]**
- 결과는 안드로이드 앱과 홈 화면 위젯으로 본다. **[결정]**

사용자는 본인 한 명이다. Play 스토어에 올리지 않고 APK를 직접 설치한다. **[제안]**

## 3. 목표 · 비목표 · 실패 조건

**목표**

- 위젯에서 출근·퇴근 지수, 등급, 한 줄 근거를 본다.
- 지수는 Claude가 5개 예보 모델의 데이터와 결빙 추정 근거를 보고 산출한다. **[결정]**
- 앱 화면에서 슬롯별 판단 근거와 모델별 시간대 데이터를 본다.

**비목표**

- 경로 위 여러 지점 분석, 내비게이션
- 푸시 알림 (나중 후보)
- 주말 라이딩, 임의 목적지
- 전날 밤 다음 날 지수 미리보기 [결정]
- 현재 위치 기준 지수 [결정]

**실패 조건** — 동작은 해도 실패로 본다.

1. 눈이나 결빙 위험이 있는데 "좋음" 등급이 나온다.
2. 출근 직전에 위젯이 전날 값을 보여 주면서 그 사실을 표시하지 않는다.
3. 집·회사 좌표가 공개 저장소나 GitHub Pages에 올라간다.

## 4. 검토한 방식

| 결정 사항 | 검토한 안 | 선택 |
|---|---|---|
| 날씨 출처 | A. Open-Meteo 한 곳에서 예보 모델 5개 / B. 서비스 5곳을 각각 연결 | **A를 바탕으로 기상청 단기예보 API를 첫 버전에 포함** [제안 — 사용자가 키 동작 확인]. Open-Meteo의 기상청 모델(`kma_seamless`·`kma_ldps`·`kma_gdps`)은 2026-11-23 서울 좌표에서 값이 모두 비어 있었다. 그래서 Open-Meteo 4개 모델과 기상청 단기예보 직접 조회를 합쳐 5개로 한다 |
| Claude 호출 경로 | 앱에서 Claude API 직접 호출(API 키, 사용량 과금) / GitHub Actions에서 `claude-code-action`을 구독 OAuth 토큰으로 실행 | **GitHub Actions** [결정]. 사용자의 기존 `lepela/bombom-menu`와 같은 구조다 |
| Claude 역할 | 1안. 지수는 규칙으로 계산하고 Claude는 해설만 / 2안. Claude가 지수까지 산출 | **2안** [결정] |

2안의 약점은 같은 날씨에도 점수가 몇 점씩 달라질 수 있다는 것, Claude 실행이 실패하면 지수가 없다는 것이다. 이를 막기 위해 아래 세 가지를 덧붙인다. **[제안]**

- 규칙으로 계산한 기준 점수를 Claude에게 참고값으로 준다. 기준 점수와 15점 넘게 차이 나면 이유를 반드시 적게 한다.
- 안전 하한(5.4절)은 Claude 결과와 상관없이 코드가 강제한다.
- Claude 실행이 실패하면 기준 점수를 게시하고 `source: "rule"`로 표시한다.

## 5. 클라우드 쪽 — GitHub Actions

### 5.1 저장소와 실행 시각

- 새 공개 저장소 하나. 이름은 빌더가 정한다. 결과는 `docs/`를 GitHub Pages로 게시한다. **[제안]**
- 실행 시각 **[제안]**

  | 실행 | KST | cron (UTC) | 산출 슬롯 |
  |---|---|---|---|
  | 아침 | 평일 06:30 | `30 21 * * 0-4` | 출근 + 퇴근 |
  | 오후 | 평일 17:00 | `0 8 * * 1-5` | 퇴근 (갱신) |

  - 아침 실행에서 퇴근 슬롯까지 함께 내는 이유: 아침에 탈지 정할 때 돌아오는 길 날씨도 필요하다.
  - GitHub cron은 수십 분 늦게 시작할 수 있다. 봄봄과 같이 Claude 클라우드 루틴으로 `workflow_dispatch`를 한 번 더 실행해 이중화한다. 이미 같은 실행분이 게시돼 있으면 아무것도 하지 않는다(멱등). 루틴 생성은 빌드 범위에 넣고, 만들기 직전에 사용자 확인을 받는다. **[제안]**
- 좌표는 Secrets에 둔다: `HOME_LAT`, `HOME_LON`, `WORK_LAT`, `WORK_LON`. Claude 토큰은 `CLAUDE_CODE_OAUTH_TOKEN`. 기상청 인증키는 `KMA_SERVICE_KEY`로, 디코딩한 값을 넣는다. 요청할 때 코드가 URL 인코딩한다.

### 5.2 단계

1. **fetch** — 집·회사 두 좌표에 대해 Open-Meteo 4개 모델(과거 48시간과 오늘·내일)과 기상청 단기예보를 받는다.
2. **features** — 슬롯별 요약값, 결빙 위험도(5.5절), 기준 점수를 계산해 Claude 입력 파일을 만든다. 입력 파일에는 좌표를 넣지 않는다.
3. **claude** — `anthropics/claude-code-action`이 입력 파일과 기준표(`rules.json`)를 읽고 결과 JSON을 쓴다. 도구는 Read·Write 위주로 제한한다. 커밋은 하지 않는다.
4. **validate** — 스키마를 검증하고 안전 하한을 적용한다. Claude 결과가 없거나 스키마가 틀리면 기준 점수로 대체한다.
5. **publish** — `docs/latest.json`과 `docs/history/YYYY-MM-DD-am.json`(또는 `-pm`)을 커밋한다.

### 5.3 Open-Meteo 요청

- 엔드포인트: `https://api.open-meteo.com/v1/forecast`
- 모델 **[제안]**: `ecmwf_ifs025`, `gfs_seamless`, `icon_seamless`, `jma_seamless`
  - 2026-11-23 서울 좌표로 실제 조회한 결과, `kma_seamless`·`kma_ldps`·`kma_gdps`는 모든 값이 `null`이었다. 기상청 예보는 5.3a의 단기예보 API로 직접 받는다.
  - `ukmo_seamless`·`metno_seamless`도 값이 나온다. 기상청 단기예보를 받지 못하는 날이 잦으면 `ukmo_seamless`를 다섯 번째로 넣는 것을 검토한다.
  - 모델 목록은 `rules.json`에 두고, 응답에서 기온이 모두 `null`인 모델은 그 실행에서 빼고 `models_used`에 남기지 않는다.
- 시간별 변수: `temperature_2m`, `apparent_temperature`, `dew_point_2m`, `precipitation`, `rain`, `snowfall`, `snow_depth`, `precipitation_probability`, `wind_gusts_10m`, `soil_temperature_0cm`
  - `soil_temperature_0cm`(지표면 온도)는 노면 온도 근사값으로 쓴다.
  - 모델마다 주는 변수가 다르다. 없는 값은 `null`로 두고 Claude 입력에 "제공 안 함"으로 적는다.
- `past_days=2`, `forecast_days=2`, `timezone=Asia/Seoul`
- 여러 모델을 한 번에 요청하면 응답 키에 모델 이름이 붙는다(예: `temperature_2m_icon_seamless`). 단위는 강수 mm, 적설 cm.
- 2026-11-23 서울 좌표 실측: 4개 모델 모두 기온·강수·적설·이슬점·체감온도를 준다. `soil_temperature_0cm`은 ECMWF·ICON만, `wind_gusts_10m`은 JMA를 뺀 3개만, `precipitation_probability`는 JMA를 뺀 3개만 준다.

### 5.3a 기상청 단기예보 **[제안]**

- 엔드포인트: `https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getVilageFcst`, `dataType=JSON`, `numOfRows=1000`
- 좌표는 기상청 격자(nx, ny)로 바꿔 요청한다. 변환은 기상청 동네예보 람베르트 정각원추도법 공식(RE 6371.00877 km, GRID 5.0 km, SLAT1 30°, SLAT2 60°, OLON 126°, OLAT 38°, XO 43, YO 136)을 쓴다. 서울시청(37.5665, 126.9780)은 (60, 127)이 나와야 한다.
- 발표 시각은 02·05·08·11·14·17·20·23시이고 발표 후 10분부터 조회된다. 실행 시각 기준으로 가장 최근 발표분을 쓴다(06:30 실행 → 05시, 17:00 실행 → 14시).
- 쓰는 항목과 해석

  | 항목 | 뜻 | 숫자로 바꾸는 규칙 |
  |---|---|---|
  | `TMP` | 1시간 기온 °C | 그대로 |
  | `PCP` | 1시간 강수량 | "강수없음" 0, "1mm 미만" 0.5, "N.Nmm" N.N, "30.0~50.0mm" 40, "50.0mm 이상" 50 |
  | `SNO` | 1시간 신적설 | "적설없음" 0, "1cm 미만" 0.5, "N.Ncm" N.N, "5.0cm 이상" 5 |
  | `PTY` | 강수형태 | 0 없음, 1 비, 2 비/눈, 3 눈, 4 소나기 |
  | `POP` | 강수확률 % | 그대로 |
  | `WSD` | 풍속 m/s | 그대로. 돌풍 값은 없다 |

- `SNO > 0` 이거나 `PTY`가 2·3인 시간이 슬롯 창에 있으면 적설 예보 모델로 센다.
- 단기예보는 미래 예보만 준다. 지난 48시간 강수·적설, 이슬점, 체감온도, 지표면 온도는 이 출처에서 `null`이다.
- 모델 이름은 `kma_vilage`로 쓴다.
- 조회에 실패하면(해외 IP 차단, 키 오류, 시간 초과) 이 출처를 `null`로 두고 4개로 계속 진행한다. 게시 JSON의 `models_used`에서 빠진다.

### 5.4 지수 정의

- 0~100점. 높을수록 타기 좋다.
- 등급 **[제안]**

  | 점수 | 등급 | 위젯 색 |
  |---|---|---|
  | 80~100 | 좋음 | 초록 |
  | 60~79 | 주의 | 노랑 |
  | 40~59 | 비추천 | 주황 |
  | 0~39 | 타지 않음 | 빨강 |

- 슬롯 창 **[제안]**: 출근은 집 08:00~09:00과 회사 08:30~09:30, 퇴근은 회사 18:00~19:00과 집 18:30~19:30. 두 지점 중 나쁜 쪽을 따른다.
- Claude 판단 기준표 — 프롬프트와 `rules.json`에 넣는다. 수치는 모두 초안이며 `rules.json`에서 조정한다. **[제안]**

  | 요소 | 기준 초안 |
  |---|---|
  | 강수 | 시간당 0.1mm 미만은 영향 없음. 1mm 미만 소폭 감점, 1~3mm 중간 감점, 3mm 이상 큰 감점. 모델 간 합의 정도를 반영 |
  | 눈 | 슬롯 창에 적설을 예보한 모델 수에 따라 큰 감점 |
  | 결빙 | 5.5절 위험도 |
  | 추위 | 체감온도 0°C 이하부터 감점, -5°C 이하 큰 감점 |
  | 돌풍 | 15m/s 이상 감점 (사용자 언급 없음, 설계자 추가) |
  | 모델 불일치 | 점수와 별도로 신뢰도(높음·보통·낮음)로 표시 |

- 안전 하한 — validate 단계가 강제한다. Claude 점수가 이보다 높으면 내리고 `floor_applied`에 적는다. **[제안]**
  - 슬롯 창에 적설을 예보한 모델이 2개 이상 → 39점 이하
  - 결빙 위험 "높음" → 39점 이하
  - 결빙 위험 "낮음" 또는 적설 예보 모델 1개 → 59점 이하

### 5.5 결빙 위험 추정 (규칙)

노면 온도는 직접 받지 못하므로 아래 조건으로 추정한다. **[결정: 추정치 사용 / 제안: 조건]**

| 위험도 | 조건 (슬롯 창 기준, 5개 모델 중앙값) |
|---|---|
| 높음 | 지난 48시간 적설 > 0 이고, (기온 ≤ 1°C 또는 지표면 온도 ≤ 0°C) |
| 낮음 | 지난 24시간 강수 ≥ 1mm 이고 기온 ≤ 3°C, 또는 기온 ≤ 2°C 이고 이슬점과의 차이 ≤ 1°C (서리) |
| 없음 | 그 외 |

Claude에게는 위험도와 함께 원자료(과거 48시간 강수·적설, 기온, 이슬점, 지표면 온도)를 넘긴다. 위험도 판정 자체를 Claude가 바꾸지는 못한다. 안전 하한이 이 판정을 기준으로 걸린다.

## 6. 안드로이드 앱

- Kotlin, Jetpack Compose, 위젯은 Glance, 백그라운드 갱신은 WorkManager. **[제안]**
- minSdk 26. **[제안]**

### 6.1 위젯

```
┌─────────────────────────────┐
│ 출근 08:30   72  주의        │
│ 약한 비 0.3~0.8mm/h          │
│ 퇴근 18:30   35  타지 않음    │
│ 결빙 위험 높음 (안전 하한)     │
│ 06:34 갱신 · Claude          │
└─────────────────────────────┘
```

- 출근·퇴근 두 칸. 점수, 등급 색, 한 줄 요약, 갱신 시각, 출처(Claude/규칙)를 표시한다.
- 출근 시각이 지나면 출근 칸은 흐리게 표시한다. **[제안]**

### 6.2 갱신과 대체 순서

- 07:00과 17:30 직후에 1회성 작업으로 `latest.json`을 받는다. 그 외에는 1시간 주기로 받는다. 위젯을 탭하면 즉시 받는다. **[제안]**
- 위젯에 표시할 값은 아래 순서로 고른다. **[제안]**
  1. `latest.json`의 슬롯 날짜가 오늘이면 그 값. 출처 "Claude" 또는 "규칙"(Actions가 규칙으로 대체한 경우)
  2. 1이 없거나 날짜가 오늘이 아니면, 앱이 등록된 집·회사 좌표로 계산한 대체 점수(6.4절). 출처 "자체 계산"
  3. 2도 실패하면(네트워크 없음 등) 마지막으로 받은 값에 "어제 값" 표시를 붙여 보여 준다(실패 조건 2)

### 6.3 앱 화면

- 슬롯별 카드: 점수, 등급, 신뢰도, Claude 근거 목록, 기준 점수와의 차이, 안전 하한 적용 여부
- 모델별 시간대 표: 슬롯 창의 강수·적설·기온을 5개 모델별로 표시
- 설정: Pages 주소, 집·회사 좌표 등록(6.4절)

### 6.4 집·회사 등록과 대체 점수 (GPS)

Claude 지수는 클라우드에서 계산하므로 휴대폰 GPS를 받을 수 없다. 그래서 GPS는 두 좌표를 등록할 때만 쓴다. **[결정]**

- 설정 화면에 "지금 위치를 집으로 등록", "지금 위치를 회사로 등록" 버튼을 둔다. 누르면 GPS 좌표를 앱 안에만 저장한다.
- 등록한 좌표를 화면에 보여 주고 복사할 수 있게 한다. 사용자는 이 값을 GitHub Secrets(`HOME_LAT` 등)에 한 번 넣는다. 앱이 GitHub에 직접 올리지는 않는다. **[제안]**
- 대체 점수: 앱이 두 좌표로 Open-Meteo 4개 모델을 조회하고, `rules.json` 기준값으로 5.4절 슬롯 창·안전 하한과 5.5절 결빙 위험도를 기기 안에서 계산한다. Claude는 거치지 않는다. 기상청 단기예보는 쓰지 않는다. 인증키를 앱에 넣지 않기 위해서다. **[제안]**

규칙 계산은 Python(Actions)과 Kotlin(앱)에 두 번 구현된다. 같은 입력에 같은 결과가 나오는지 확인하는 공용 테스트 케이스(JSON)를 저장소에 둔다.
