# 출퇴근 바이크 주행 지수 산출

이 작업은 파일 하나를 읽고 파일 하나를 쓰는 것으로 끝난다.

1. `work/claude_input.json`을 Read 도구로 읽는다. 경로를 찾으려고 탐색하지 않는다.
2. 아래 기준으로 슬롯마다 주행 지수를 정한다.
3. `work/claude_output.json` 하나만 Write 도구로 만든다. 다른 파일은 만들거나 고치지 않고, git 명령은 쓰지 않는다.

## 사용자 기준

- 평일 출근 08:30, 퇴근 18:30에 바이크를 탄다. 매일 같은 길이다.
- 비가 온다고 무조건 타지 않는 것은 아니다. 강수량에 따라 판단한다.
- 눈은 가급적 피한다.
- 눈이 온 뒤 1~2일은 기온에 따라 도로 결빙을 따진다.

## 입력 파일

- `rubric`: 감점표(`score`), 결빙 판정 기준(`ice`), 안전 하한(`floors`), 등급(`grades`)
- `slots[]`: 슬롯마다 `rule_score`(규칙으로 계산한 기준 점수), `ice_risk`, `confidence`, `floor_cap`·`floor_label`, `features`(모델 중앙값과 두 지점 중 나쁜 쪽), `hourly`(지점·모델별 시간 값)
- 모델 이름 `kma_vilage`는 기상청 단기예보다. `pty`는 강수형태(0 없음, 1 비, 2 비/눈, 3 눈, 4 소나기)다.
- 값이 `null`이면 그 모델이 그 변수를 주지 않은 것이다.

## 판단

- 점수는 0~100 정수다. 높을수록 타기 좋다.
- `rubric`의 감점표를 기준으로 삼는다. 모델 간 차이, 시간대별 흐름, 강수형태를 보고 조정한다.
- `rule_score`와 15점 넘게 다르면 `deviation_reason`에 그 이유를 한 문장으로 쓴다. 15점 이내면 `null`로 둔다.
- 결빙 위험도와 안전 하한은 코드가 다시 적용한다. 점수에 반영하되 판정을 바꾸려 하지 않는다.
- `confidence`는 모델들이 얼마나 일치하는지로 정한다. `높음`·`보통`·`낮음` 중 하나다.
- `summary`는 60자 이내 한국어 한 줄이다. 강수량·적설·결빙·기온 중 판단에 쓴 사실을 적는다.
- `reasons`는 한국어 문장 1~4개다. 사실만 적고 권유하지 않는다.

## 출력 형식

아래 키만 쓴다. 다른 키를 더하지 않는다. 입력의 슬롯 `id`를 빠짐없이, 한 번씩만 넣는다.

```json
{
  "slots": [
    {
      "id": "commute_in",
      "score": 72,
      "confidence": "보통",
      "summary": "오전 약한 비 0.3~0.8mm/h, 결빙 없음",
      "reasons": ["5개 모델 중 4개가 약한 비", "기온 4°C"],
      "deviation_reason": null
    }
  ]
}
```

파일을 쓴 뒤에는 아무것도 하지 않는다.
